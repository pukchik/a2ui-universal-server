# Личные заметки: отдельное приложение

Пример использует публичную точку входа `server/index.ts`, собственную авторизацию, инструменты и детерминированный адаптер. Файлы демки ламп не импортируются. Два учебных пользователя видят разные записи: обработчик фильтрует их по `ToolContext.userId`, полученному из БД сервера.

Из корня checkout, с отдельной PostgreSQL:

```sh
DATABASE_URL=postgres://USER:PASSWORD@localhost:5432/notes_example PORT=3120 PUBLIC_URL=http://localhost:3120 node examples/notes/app.ts
```

Codex и OIDC не нужны. Это локальный HTTP-пример, отдельного веб-интерфейса у него нет. `GET http://localhost:3120/auth/login?user=alice` создаёт непрозрачную cookie; `user=bob` выбирает второго учебного пользователя. Затем получите `/v1/session`, передавайте cookie, Origin и CSRF, создайте диалог и отправьте сообщение по [API](../../docs/API.md).

Этот вход — только для учебного loopback-примера, без проверки пароля. Для собственного приложения замените `AuthProvider` на чтение его настоящей сессии. Хранилище учебных сессий находится в памяти, заметки заданы в коде; состояние диалога, UI, команды и вызовы инструментов сохраняются в PostgreSQL.

`notesOptions()` собирает auth/tools/adapter, `startNotesExample()` вызывает общий `startServer`. Остановка — Ctrl+C. `get_note` проверяет владельца даже при передаче существующего чужого ID. Действие `open_note` продолжает диалог и обновляет поверхность; форма `search` фильтрует свои записи. Нажатие передаётся с текущей `uiRevision`.

`tests/integration.test.ts` проверяет HTTP, UI, прямые/MCP-вызовы, подмену владельца, CSRF, отмену, блокировку и остановку. `tests/external-project.test.ts` переносит приложение во временную папку с явными импортами checkout и запускает отдельным Node-процессом: генерация, действие, восстановление, SIGTERM. Это проверка использования исходников вне cwd сервера, не публикация npm-пакета и не браузерный прогон. Полный запуск обоих наборов требует `TEST_DATABASE_URL`.
