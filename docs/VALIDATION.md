# Проверка первой версии

Проверено локально 21 октября 2026 года. Это результаты конкретного прогона, а не заявление о готовности публичной многосерверной установки.

| Проверка | Результат |
| --- | --- |
| `pnpm build` | TypeScript и production-сборка клиента проходят |
| `TEST_DATABASE_URL=… pnpm test` | 38 тестов в 5 файлах проходит с отдельной PostgreSQL 18.6 |
| Официальный Codex SDK 0.163.0 + CLI 0.163.0, `pnpm smoke:codex` | Настоящий `search_products` через MCP, принятый A2UI, затем действие `show_product`, настоящий `get_product` и увеличение ревизии UI |
| Браузер, официальный Lit renderer 0.14.0 | Поиск, поле уточнения, отправка формы, карточки, «Подробнее» и восстановление страницы |
| OIDC, Keycloak 26.4.2 | Вход тестового пользователя через redirect/callback и серверная сессия |
| `docker build --network host -t a2ui-uniserver:0.1.0 .` | Образ на Node.js 24 собирается с установкой из lockfile |
| SDK под Node.js 24.22.0 в контейнере | От пользователя `node`, с текущим кодом и зависимостями через read-only mount, имитатор CLI возвращает итоговый ответ через официальный SDK |

Автоматические тесты проверяют официальный протокол и профиль компонентов, атомарность пакетов, ссылки и циклы, ревизии и контекст действий, кэш и закрепление каталога, различие модельного и агентского циклов, дедупликацию команд, изоляцию владельцев, отмену и поздние результаты, одноразовую генерацию и восстановление оборванных запусков. Имитатор CLI работает через настоящий официальный SDK и проверяет ошибки JSONL, отсутствие итогового сообщения/завершения turn, некорректный ответ, ненулевой код выхода, запрещённые инструменты и MCP, границы окружения, отсутствие MCP на исправлении, лимиты stdout/stderr и остановку группы процессов, игнорирующей SIGTERM. HTTP-проверки включают авторизацию, CSRF и наличие контрактов в OpenAPI.

В реальном прогоне через официальный SDK диалог `934e1162-ab93-4251-b2b7-beed11e7aefc` получил проверенный интерфейс после поиска и после действия. Оба MCP-вызова записаны как `succeeded`; ревизия после действия — 2. Авторизация CLI использована из существующего локального профиля без копирования credentials в проект. Для постоянной установки инструкция требует отдельного служебного профиля.

## Границы проверки

- На этой машине Docker bridge не смог создать veth. Поэтому полный `docker compose up` не подтверждён: PostgreSQL запущена локально, Keycloak — отдельным тестовым контейнером с host network и listener на loopback. Сборка образа проверена отдельно.
- Поддерживается ограниченный профиль Basic Catalog. Все компоненты A2UI, произвольные каталоги и сторонние рендереры не проверялись.
- Загрузчики HTTPS/MCP каталогов реализованы, но реальные сторонние источники в этом прогоне не подключались. Кэш и неизменность снимков проверены тестами.
- Реального API-адаптера модели нет; проверен его контракт и серверный цикл на тестовом адаптере.
- Ошибки, исправление и отмена покрыты детерминированными тестами; намеренный ошибочный ответ платного агента и падение всей ОС не моделировались. Проверка остановки CLI не заменяет проверку изоляции конкретной production-среды.
- CI, публичное развёртывание, восстановление резервной копии и нагрузочный прогон не выполнялись. История пока без пагинации и автоматической очистки; глобальная квота ожидающих заданий требует доработки перед публичной установкой.
- Сборщик предупреждает о клиентском bundle около 506 КБ до gzip; Fastify 5 предупреждает о будущем удалении `disableRequestLogging`. Это не ошибки сборки или тестов, но их нужно учесть при обновлении зависимостей.

Команды воспроизведения и требования к отдельной тестовой БД находятся в [RUNNING.md](RUNNING.md). Без `TEST_DATABASE_URL` часть проверок явно пропускается.
