# Проверки и границы готовности

Состояние интегрируемой версии сверено 22 октября 2026 года: сервер находится в `server/`, адаптер — в `server/adapters/codex/`, каталог UI — в `catalog/`, демоприложение — в `demo/`, отдельные примеры — в `examples/notes/` и `examples/custom-catalog/`. Ниже разделены автоматические и ранее выполненные ручные проверки. Документация не объявляет публичную многопользовательскую платформу полностью готовой.

| `tests/components.test.ts` | 53 проверки семи компонентов: схемы, `$ref`, SDK/Lit, положительные/отрицательные примеры, передача каталога агенту                                        |
| `tests/catalogs.test.ts`   | Кэш и снимки каталога, отдельные циклы модели и готового агента                                                                                            |
| `tests/codex.test.ts`      | 13 проверок через официальный SDK и имитатор CLI: события, итог, ошибки, окружение, MCP/repair, лимиты и отмена группы процессов                           |
| `tests/store.test.ts`      | Настоящая PostgreSQL: дедупликация, владелец, состояния, отмена, инструменты, закреплённые схемы, генерация, восстановление и исправление битого JSON/A2UI |
| `tests/http.test.ts`       | Настоящая PostgreSQL и Fastify inject: сессия, CSRF, UUID, чужой ресурс, команды, MCP и OpenAPI                                                            |

Полный локальный прогон — **156 тестов в 15 файлах**, с изолированной PostgreSQL и без платной модели. Последний проверенный CI до исправления зависаний/повторов — [111](https://home.eralas.ru/git/eralash/A2UI-uniserver/actions/runs/111), 132 теста. Каждый push в main повторно проверяет полный набор и сборку того же SHA; актуальный результат виден в Actions и отдельно сообщается после отправки коммита. Подробности — в [CI.md](CI.md).

Новые наборы:

- `tests/auth.test.ts`: отсутствующие/просроченные/невалидные custom-сессии, обязательный provider, отсутствие login/logout, закрытие Store после ошибки старта, отделение Codex-конфигурации;
- `tests/integration.test.ts`: сессия существующего приложения, личные заметки, действие UI, изоляция владельцев, CSRF/Origin, прямая и MCP-передача ToolContext, сигнал отмены, единственный исполнитель, идемпотентное закрытие и потеря lock;
- `tests/external-project.test.ts`: отдельный Node-процесс из временной папки вне checkout, общий публичный API, запрос → свой инструмент → A2UI → действие → восстановление. SIGTERM завершает и обычный процесс, и процесс с зависшим обработчиком и оставленным setInterval без SIGKILL.
- `tests/profiles.test.ts`: собственный StatusBadge, несовместимые модели/данные, локальный источник, метаданные сохранённого профиля после смены стандартного и отказ без зарегистрированной модели;
- `tests/maintenance.test.ts`: dry-run, удаление тестовой истории и связанных данных, tombstone/410, сохранение активных запусков и их команд, batch/lock, истёкшие сессии, периодическое обслуживание и конкурентный приём 12 запросов разных пользователей при общей квоте 3;
- `tests/runtime.test.ts`: выбор только старых завершённых runtime, ограничения путей, symlink, batch и повторная проверка состояния; подставной runner проверяет точные аргументы `rm`, сами тестовые файлы не удаляются.
- `tests/openapi.test.ts`: 19 публичных операций, уникальные operationId, описания/ответы/security, разрешимость ссылок на модели, корректный SSE, локальные ресурсы Swagger и совпадение документов, автоген новой операции, CSRF для своего origin и загрузка спецификации без method. Подключение БД этому набору не нужно.
- `tests/deadlines.test.ts`: не отвечающие на signal готовый агент, модель, инструмент и repair; освобождение слота, отзыв токена, сохранение terminal-статуса и отклонение поздних результатов. Проверяются отмена, остановка с двухсекундным пределом ожидания и завершение cooperative cleanup до закрытия Store.
- `tests/client.test.ts`: сохранение UUID/тела после 5xx, 408, сетевой ошибки и некорректного ответа; новый CSRF, неизменность вложенного тела и параллельные retry. PostgreSQL/HTTP проверяет потерю ответа после принятия команды: повтор возвращает исходный диалог, в БД остаётся один.

Исполнитель тестируется с битой JSON-строкой, корректным JSON неправильной структуры и сообщением с нарушенной схемой A2UI. Он допускает одно исправление без инструментов. Повторная ошибка завершает запуск, не публикует отвергнутый текст, не создаёт нового `ui.updated` и сохраняет прежний UI. Проверка каталога подтверждает, что старый диалог сохраняет старые ограничения, новый использует изменённые.

Воспроизведение из корня:

```sh
make check
pnpm build
make test-components
TEST_DATABASE_URL=postgres://USER:PASSWORD@localhost:5432/a2ui_test pnpm test
```

Используйте отдельную тестовую БД, без работающего исполнителя. Без `TEST_DATABASE_URL` PostgreSQL/HTTP явно пропускаются: это неполный прогон. Набор maintenance проверяет удаление записей по TTL внутри указанной БД, поэтому пользовательская/рабочая БД для тестов не подходит. Изолированный кластер ниже создаёт только тестовые данные.

Изолированный кластер PostgreSQL без TCP:

```sh
PG_BIN=/usr/bin pnpm test:ci
# Укажите каталог с initdb/pg_ctl/createdb вашей установки.
# В CI используется /usr/lib/postgresql/18/bin.
```

Скрипт создаёт временный кластер, выполняет полный Vitest и останавливает PostgreSQL при выходе; существующие БД и файлы не удаляет. Для VS Code используйте расширение Vitest, дерево `tests`; Jest для этого проекта не требуется.

## Проверки запуска и клиента

OpenAPI экспортирован командой `pnpm openapi` без БД/модели и разобран как JSON. Swagger UI проверен в Chromium: загрузка спецификации, локальный вход через Execute (200), создание диалога (201) с cookie браузера и автоматически полученным CSRF; ошибок консоли нет. После добавления схем ответов штатный HTTP smoke снова прошёл генерацию → действие до UI revision 2. Форматирование, типы и production-сборка прошли. Браузерные артефакты этой проверки сохранены вне checkout, в `/tmp`.

До этапа интеграции отдельно проверены `make check`, production-сборка, `pnpm db:migrate`, запуск `make demo`, загрузка JS/CSS, вход и цикл генерация → форма → UI revision 2. `make run` с адаптером Codex и локальным входом также проверялся; сам запуск сервера не является проверкой ответа модели. Экспорт каталога и обратная загрузка локального документа сохраняют digest. Compose прошёл `config --quiet`.

После перехода на `startServer` повторно прошли форматирование, TypeScript и production-сборка. Штатная точка входа с fixture проверена через HTTP: ресурсы, вход, генерация и действие до UI revision 2. С существующим служебным профилем также запущен адаптер Codex: health и метка адаптера корректны, запрос к платной модели не выполнялся. Оба процесса корректно остановлены.

Собственный `StatusBadge` из `examples/custom-catalog` проверен в Chromium через Vite и официальный Lit renderer: элемент с `role=status` показывает «Собственный компонент работает», ошибок JavaScript нет. Это статический технический preview; отдельный запрос к модели с этим компонентом не выполнялся. После миграции 0004 штатная fixture-демка снова прошла вход → генерация → действие до UI revision 2; `pnpm maintenance` вернула dry-run без изменений. CLI очистки файлов проверяется с подставным runner; реальное удаление пользовательских runtime не выполнялось.

Ранее 21 октября 2026 года отдельно выполнены:

- настоящий Codex SDK/CLI 0.163.0: MCP `search_products` → принятый A2UI → действие `show_product` → MCP `get_product` → UI revision 2;
- OIDC-вход тестового пользователя через Keycloak 26.4.2 и callback;
- официальный Lit renderer 0.14.0: поиск, ввод формы, «Подробнее», reload и мобильные вкладки; inspector на 1440/768/390 px показал 0 FAIL / 0 WARN, подробности в [demo/DESIGN.md](../demo/DESIGN.md);
- Docker-образ до переноса исходников и SDK от пользователя `node` под Node.js 24.22.0 через read-only mount.

Эти ручные прогоны не запускаются в CI автоматически. После перемещения файлов новый Docker-образ полностью не пересобирался. Команда текущей сборки: `docker build -f demo/Dockerfile -t a2ui-uniserver:0.1.0 .`. Docker bridge на этой машине не смог создать veth, поэтому полноценный `docker compose up` всех сервисов не подтверждён: PostgreSQL и Keycloak проверялись отдельно. Не переносите статус проверки образа на статус сетевого Compose-запуска.

Для повторной платной проверки: `pnpm smoke:codex` с отдельной БД и служебным профилем; требования — в [demo/README.md](../demo/README.md). Credentials в проект не копируются. Намеренное падение всей ОС или ошибочный платный ответ агента не моделировались.

## Проверка документации

Для обновлённых инструкций проверяются локальные ссылки и якоря Markdown-файлов, типы примеров из INTEGRATION и приём A2UI-примера из STACK настоящим валидатором. Точка входа из инструкции запущена с отдельной PostgreSQL: health, demo-вход, создание диалога и снимок прошли. Модель в этом прогоне не вызывалась; полный сценарий пользовательского приложения всё равно нужно проверить после подстановки его инструментов и renderer.

## Оставшиеся ограничения

- Проверены официальный Lit renderer, ограниченный Basic Catalog и один собственный компонент. Другие библиотеки renderer и все компоненты A2UI не проверены. HTTPS/MCP-загрузчики каталогов не проверялись на реальных сторонних источниках.
- `execute(args, context)` получает проверенного владельца и сигнал отмены. Готовые предметные ACL, контекст организации и согласование записей не реализованы; фильтрацию личных ресурсов делает обработчик.
- Реального API-адаптера модели нет, только контракт и тестовый цикл. Отмена не доказывает изоляцию произвольной production-среды.
- Публичное развёртывание, восстановление backup и нагрузочный прогон не выполнялись. CD отключён. Масштабирование исполнителей и пагинация истории требуют работы. Квоты и retention проверены функционально на изолированных данных, не под производственной нагрузкой.
- Клиентский bundle около 514 КБ до gzip вызывает предупреждение Vite. Fastify 5 предупреждает о будущем удалении `disableRequestLogging`. Это текущие предупреждения, не ошибки проверенных сборок.
