Полный прогон — **97 тестов в 6 файлах**, без платной модели. Он прошёл локально и на Страже: [CI 107](https://home.eralas.ru/git/eralash/A2UI-uniserver/actions/runs/107), `tests` 51 с, зависимая `build` 24 с, проверен один SHA. Подробности и кэш — в [CI.md](CI.md).

Исполнитель тестируется с битой JSON-строкой, корректным JSON неправильной структуры и сообщением с нарушенной схемой A2UI. Он допускает одно исправление без инструментов. Повторная ошибка завершает запуск, не публикует отвергнутый текст, не создаёт нового `ui.updated` и сохраняет прежний UI. Проверка каталога подтверждает, что старый диалог сохраняет старые ограничения, новый использует изменённые.

Воспроизведение из корня:

```sh
make check
pnpm build
make test-components
TEST_DATABASE_URL=postgres://USER:PASSWORD@localhost:5432/a2ui_test pnpm test
```

Используйте отдельную тестовую БД, без работающего исполнителя. Без `TEST_DATABASE_URL` PostgreSQL/HTTP явно пропускаются: это неполный прогон. Тесты создают записи с уникальными ID; автоматической очистки БД нет.

Изолированный кластер PostgreSQL без TCP:

```sh
PG_BIN=/usr/bin pnpm test:ci
# Укажите каталог с initdb/pg_ctl/createdb вашей установки.
# В CI используется /usr/lib/postgresql/18/bin.
```

Скрипт создаёт временный кластер, выполняет полный Vitest и останавливает PostgreSQL при выходе; существующие БД и файлы не удаляет. Для VS Code используйте расширение Vitest, дерево `tests`; Jest для этого проекта не требуется.

## Проверки запуска и клиента

После переноса сервера проверены `make check`, production-сборка, `pnpm db:migrate`, запуск `make demo`, загрузка JS/CSS, вход и цикл генерация → форма → UI revision 2. `make run` с адаптером Codex и локальным входом также проверялся; сам запуск сервера не является проверкой ответа модели. Экспорт каталога и обратная загрузка локального документа сохраняют digest. Compose прошёл `config --quiet`.

Ранее 21 октября 2026 года отдельно выполнены:

- настоящий Codex SDK/CLI 0.163.0: MCP `search_products` → принятый A2UI → действие `show_product` → MCP `get_product` → UI revision 2;
- OIDC-вход тестового пользователя через Keycloak 26.4.2 и callback;
- официальный Lit renderer 0.14.0: поиск, ввод формы, «Подробнее», reload и мобильные вкладки; inspector на 1440/768/390 px показал 0 FAIL / 0 WARN, подробности в [demo/DESIGN.md](../demo/DESIGN.md);
- Docker-образ до переноса исходников и SDK от пользователя `node` под Node.js 24.22.0 через read-only mount.

Эти ручные прогоны не запускаются в CI автоматически. После перемещения файлов новый Docker-образ полностью не пересобирался. Команда текущей сборки: `docker build -f demo/Dockerfile -t a2ui-uniserver:0.1.0 .`. Docker bridge на этой машине не смог создать veth, поэтому полноценный `docker compose up` всех сервисов не подтверждён: PostgreSQL и Keycloak проверялись отдельно. Не переносите статус проверки образа на статус сетевого Compose-запуска.

Для повторной платной проверки: `pnpm smoke:codex` с отдельной БД и служебным профилем; требования — в [demo/README.md](../demo/README.md). Credentials в проект не копируются. Намеренное падение всей ОС или ошибочный платный ответ агента не моделировались.

## Оставшиеся ограничения

- Проверены один renderer и ограниченный Basic Catalog, не все компоненты A2UI и сторонние клиенты. HTTPS/MCP-загрузчики каталогов не проверялись на реальных сторонних источниках.
- `execute(args)` не получает проверенного пользователя; предметные ACL, организации и согласование записей не реализованы.
- Реального API-адаптера модели нет, только контракт и тестовый цикл. Отмена не доказывает изоляцию произвольной production-среды.
- Публичное развёртывание, восстановление backup и нагрузочный прогон не выполнялись. CD отключён. Масштабирование исполнителей, пагинация/очистка истории, runtime и глобальные квоты требуют работы.
- Клиентский bundle около 514 КБ до gzip вызывает предупреждение Vite. Fastify 5 предупреждает о будущем удалении `disableRequestLogging`. Это текущие предупреждения, не ошибки проверенных сборок.
