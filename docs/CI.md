# CI в Gitea

Workflow `.gitea/workflows/ci.yml` запускается на push в `main` и вручную через Actions. На общем runner со связью с сетью хоста проверяется только доверенный код; автоматического запуска для внешних pull requests нет.

Три job с отдельными checkout:

1. `tests`: установка из lockfile, форматирование, синтаксис служебного shell-скрипта, TypeScript и полный Vitest с отдельной PostgreSQL 18.
2. `build`: только после успешной `tests`, свежий checkout её точного SHA, повторная установка из lockfile и production-сборка клиента.
3. `deploy`: после успешных `tests` и `build`, тот же SHA, сборка с префиксом стенда, публикация штатным клиентом и smoke test.

PostgreSQL ставится из официального PGDG-репозитория внутри временного job-контейнера. Для каждого прогона `scripts/test-ci.sh` создаёт отдельный кластер и БД, выключает TCP, подключает тесты через Unix-сокет и останавливает сервер при выходе. Производственная БД и секреты приложения не нужны. Скрипт не удаляет существующие базы или каталоги. Runtime-данные остаются внутри временного контейнера и не попадают в кэш.

Кэшируются только скачанные пакеты pnpm. Ключ учитывает проект, ОС/архитектуру, Node.js, версию pnpm и lockfile; установка всегда выполняется с `--frozen-lockfile`. Jobs работают и без кэша. Кэш runner проверен включённым на Страже; Node.js-образ закреплён digest. PostgreSQL устанавливается только в `tests`; общий образ runner ради проекта не изменяется. Повторная установка apt-пакетов остаётся затратой подготовки job; отдельный готовый CI-образ можно согласовать, если замеры покажут необходимость.

Настоящий Codex и браузерные сценарии проверяются отдельно: CI не получает авторизацию модели и не расходует её лимиты. Runner не получает Docker socket: backend-образ собирает штатный шлюз во время публикации. Проверка `pnpm build` остаётся отдельной от проверки контейнерного запуска.

## Проверка на Страже

21 октября 2026 года [запуск 99](https://home.eralas.ru/git/eralash/A2UI-uniserver/actions/runs/99) на commit `a71b412` завершился успешно: все 38 тестов прошли, затем `build` получила тот же SHA и собрала production-клиент. `tests` заняла 86 секунд, `build` — 24 секунды.

На первом запуске `tests` получила cache miss и сохранила кэш pnpm около 192 МБ. Независимая `build` восстановила его с cache hit. Установка зависимостей заняла 11,5 секунды без кэша и 4,8 секунды после восстановления; само восстановление добавило около 7 секунд. Это подтверждение работы кэша и сокращения повторных скачиваний, а не обещание ускорения каждого запуска. Установка PostgreSQL заняла 13 секунд; отдельный общий CI-образ пока не требуется.

Зависимость `needs: tests` и порядок jobs проверены. Намеренно ломающий тестовый commit не публиковался; отдельного эксперимента с отказом всего workflow не было.

## Автодеплой демостенда

После первоначальной настройки CI владелец запросил демку на каждый commit. Для неё включён отдельный временный профиль с fixture-адаптером и PostgreSQL внутри backend-контейнера, без авторизации модели. Данные сбрасываются при перезапуске. Устройство и проверки — в [DEMO.md](DEMO.md).

Deploy credentials доступны только шагу Publish. Полноценная постоянная установка с Codex, OIDC и внешней БД остаётся отдельной задачей.

Первый полный [запуск 101](https://home.eralas.ru/git/eralash/A2UI-uniserver/actions/runs/101) на commit `6371ae4` прошёл 21 октября 2026 года: `tests` — 43 теста за 47 секунд, `build` — 22 секунды, затем успешная `deploy`. Проверка после публикации подтвердила точный SHA, загрузку JS/CSS, вход, генерацию и действие `search_products`. Тот же сценарий отдельно прошёл через публичный HTTPS; браузер подтвердил работу действий и восстановление диалога после перезагрузки.
