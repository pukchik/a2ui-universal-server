# Границы реализации

Ценность проекта — совместимость клиентов, агентов, каталогов и инструментов, а также управление их взаимодействием. Простой путь «промпт → A2UI JSON» является одним режимом использования.

README [serverA2ui](https://github.com/shadab5114/serverA2ui) описывает генерацию через `/generate` с загрузкой каталога из MCP на каждый запрос. Здесь этот README использован как архитектурный ориентир; выводов о корректности его исходников не делалось.

## Модель и готовый агент

Демоприложение собрано в `demo/`: его `server/app.ts` передаёт общему `buildApp` выбранный адаптер, реестр инструментов, инструкции и путь к клиенту. `apps/server` не импортирует каталог ламп, fixture или файлы `demo`. Исполнитель и MCP используют один переданный реестр. Запуск и настройка примера — в [demo/README.md](../demo/README.md).

Контракт `Adapter` различает `kind: model` и `kind: agent`. Для модели сервер вызывает `step` и выполняет предложенные инструменты, ограничивая цикл восемью шагами. Для готового агента сервер вызывает `run` один раз. Codex ведёт свой цикл внутри CLI и обращается в серверный шлюз через MCP. Второй серверный цикл вокруг инструментов Codex не запускается.

Оба варианта получают подготовленный сервером контекст, общие ограничения и сигнал отмены. Результат проходит одну проверку. Модельный контракт проверен тестовым адаптером; отдельной реальной API-интеграции модели в первой версии нет.

## Каталоги

Редактируемый источник находится в [catalog/](../catalog/README.md): метаданные и список компонентов, отдельные JSON Schema, общие определения и положительные/отрицательные примеры. Загрузчик собирает единый документ и компилирует схемы AJV без загрузки внешних ссылок. Ошибка схемы останавливает запуск. `tests/components.test.ts` отдельно проверяет схемы, примеры и наличие реализации в SDK и Lit.

`packages/catalogs` отвечает за загрузку, проверку структуры, кэш и явный `refresh`. Источники: локальный JSON, зарегистрированный HTTPS URL или инструмент MCP. Снимок документа и SHA-256 сохраняются при создании диалога/генерации. Изменение источника не меняет уже созданный контекст.

Агент получает собранный документ из этого снимка. При сохранении результата сервер проверяет свойства компонентов по тому же документу, а не по текущим файлам. Валидаторы кэшируются по содержимому схем. После редактирования файлов нужен перезапуск; изменения применяются к новым диалогам.

Встроенный клиент поддерживает один профиль Basic Catalog. Загрузка произвольного каталога не создаёт реализацию его компонентов: подключение нового профиля требует обновить клиент и соответствующую проверку сервера. Настроенный источник, не соответствующий текущему профилю, отклоняется при запуске. Кэш обновляется через реестр явно; административного HTTP endpoint обновления пока нет.

MCP загрузчика каталога и MCP инструментов приложения имеют отдельные клиенты, настройки и credentials. Загрузчик действует от имени оператора, читает описание компонентов и не получает полномочия пользовательского запуска. Внутренний MCP endpoint инструментов действует по короткоживущему токену конкретного запуска и проверяет его активность в PostgreSQL.

## Подготовка запроса и проверка результата

`prompt.ts` собирает версию протокола, закреплённый каталог, инструкции проекта, состояние задачи, историю, UI и текущий ввод. Состояние задачи хранится отдельно от UI; демонстрационный проект пока использует пустое состояние задачи. Runtime URL и bearer token MCP передаются CLI через управляемую конфигурацию и окружение, а не через промпт.

Проверки результата идут последовательно: итоговый JSON → массив сообщений → официальный валидатор A2UI → схемы Basic Catalog → профиль разрешённых компонентов → существование поверхностей и компонентов, отсутствие циклов и допустимость обновления состояния. Пакет применяется атомарно. Одна попытка исправления не имеет доступа к инструментам.

Клиентское действие передаёт диалог, поверхность, компонент, имя, контекст и ревизию. Сервер сверяет статические идентификаторы с сохранённым действием, разрешает редактируемые значения привязанных полей и затем отдельно проверяет вызовы инструментов. Неактивные и устаревшие формы не запускают агента.

## Режимы и развёртывание

Диалог сохраняет контекст для следующих команд. Разовая генерация создаёт отдельное задание и сохраняет запрос/результат для доставки и восстановления; продолжение этого задания не поддерживается. Оба режима используют одинаковые авторизацию, дедупликацию, исполнитель и лимиты.

Первая версия — один сервер с дочерними процессами Codex и PostgreSQL. Redis, брокер, Kubernetes и распределённые worker остаются отдельным профилем развития. Их появление не должно менять клиентские команды, результаты и правила доступа.

Для проверки клиента есть детерминированный адаптер с формой, действием и обновлением UI. Проверки нового адаптера должны охватывать ошибки, отмену и передачу контекста; реальные обращения к провайдеру отделены от обычного тестового прогона.
