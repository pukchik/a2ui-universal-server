# Тестовый стенд на Страже

Адрес: **https://home.eralas.ru/test/a2ui-uniserver/**. Доступ ограничивается общей LAN/VPN-защитой Стража.

Стенд обновляется после push в `main`: `tests → build → deploy`. Ошибка проверки или сборки запрещает публикацию. Deploy job делает отдельный checkout точного SHA из `tests`, собирает клиент с `BASE_PATH`, готовит разрешённый набор исходников и передаёт его штатному шлюзу. Docker собирает шлюз, а не CI runner. Новый релиз сначала проходит healthcheck; при ошибке старый продолжает работать.

## Что можно попробовать

1. Нажать «Открыть демонстрацию».
2. Написать «Покажи компактные лампы с тёплым светом».
3. Ввести «Мини» в поле уточнения и нажать «Обновить результаты».
4. Нажать «Подробнее», перезагрузить страницу и проверить восстановление.

Работают настоящий HTTP API, серверные сессии, PostgreSQL, SSE, проверки A2UI и официальный Lit-рендерер. Ответы даёт **детерминированный тестовый адаптер**. Codex и внешние инструменты не вызываются; учётные данные модели не нужны.

## Данные и ограничения

Это отдельный одноразовый профиль развёртывания: приложение и временная PostgreSQL работают в одном ограниченном backend-контейнере. PostgreSQL не слушает TCP, только приватный Unix-сокет в `/tmp`. Root filesystem остаётся read-only, runtime — UID 1000, 512 МБ RAM и 64 МБ `/tmp`, как требует шлюз. Отдельные контейнеры БД, host mounts, Docker socket и общая инфраструктура не добавляются.

Каждый вход создаёт отдельного демонстрационного пользователя. История одного браузера не выдаётся другому. **При обновлении, перезапуске или откате стенда история и сессии сбрасываются.** Временная БД работает без гарантий сохранности; настройки этого профиля нельзя использовать для пользовательских данных. Долгосрочного хранения и настоящего OIDC здесь нет.

`PUBLIC_DEMO=true` допускается только вместе с `AUTH_MODE=demo`, `ADAPTER=fixture` и HTTPS. Обычный `AUTH_MODE=demo` без этого флага сохраняет ограничение loopback. Подключение настоящего Codex требует обычной установки с OIDC, внешней PostgreSQL и отдельным служебным профилем.

## Однократные настройки оператора

Проект шлюза: `a2ui-uniserver`. Конфигурация в `strazh.deploy.json`, специальный образ — `deploy/Dockerfile.demo`, подготовка исходников — `scripts/prepare-demo.ts`. Стандартный `Dockerfile` основного приложения не меняется.

Runtime env нового проекта содержит `PUBLIC_URL=https://home.eralas.ru/test/a2ui-uniserver/`. Шлюз задаёт `BASE_PATH` и порт. В repository secret `STRAZH_DEPLOY_TOKEN` хранится только токен этого проекта. Он передаётся исключительно шагу Publish. Ни тесты, ни сборки его не получают.

После публикации `scripts/smoke-demo.ts` проверяет ожидаемый SHA через `/health`, JS/CSS, вход, генерацию A2UI и отправку формы. Публичный адрес и работу интерфейса дополнительно проверяют в браузере. Адрес API, события, ссылки входа, redirects, cookie Path и ключ локального восстановления учитывают префикс приложения.

Регистрация, runtime env, откат и ограничения — по [актуальному протоколу Стража](https://home.eralas.ru/deploy-docs/DEPLOYMENT.md). Полноценная установка с сохранением данных остаётся отдельным профилем.
