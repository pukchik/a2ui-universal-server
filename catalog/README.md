# Каталог компонентов

Здесь находится редактируемый источник каталога, который получает агент и использует сервер при проверке A2UI. Каталог больше не собирается из файлов `node_modules` при каждом запуске. Исходные схемы взяты из `@a2ui/web_core@0.14.0` и адаптированы под ограниченный профиль приложения. Лицензия исходных схем — [Apache 2.0](LICENSE).

Включены Text, Column, Row, Button, TextField, Divider и Card. Это каталог UI, общий для сервера и агента; демонстрационные товары находятся отдельно в `demo/server/tools.ts`. Подключение к собственному приложению описано в [INTEGRATION.md](../docs/INTEGRATION.md#инструкции-и-каталог).

```text
catalog.json          метаданные, версия, профиль и список компонентов
components/Text.json схема и описание одного компонента
components/…         остальные компоненты
common.json          общие типы и привязки данных
examples/Text.json   допустимые и ошибочные примеры
examples/…           примеры остальных компонентов
index.ts             загрузка и компиляция схем
```

## Редактирование

Описание компонента находится в `description`. Его свойства, допустимые значения и обязательные поля описаны JSON Schema; у текущих схем они находятся в последнем элементе `allOf`. Общие поля `id`, `accessibility` и `weight` приходят через `$ref`.

Например, в `components/Text.json` можно изменить подсказку агенту или ограничить список `variant`. Затем обновите `examples/Text.json`: в `valid` должны оставаться допустимые варианты, а в `invalid` — примеры, которые сервер обязан отклонять. Примеры содержат полное описание компонента, включая `id` и `component`.

Список включённых компонентов задаётся в `catalog.json`. Для каждого имени нужны одноимённые файлы в `components/` и `examples/`. Определения `anyComponent` и `anyFunction` собираются загрузчиком автоматически. После изменения публичного контракта обновите `version` и при необходимости `profile`; затем соберите клиент и перезапустите сервер.

Новый тип должен иметь реализацию в SDK и Lit-рендерере. Один JSON не создаёт отрисовку. Для собственного компонента сначала потребуется зарегистрировать его модель, renderer и расширить проверку совместимости. Текущий профиль поддерживает статические дочерние элементы и серверные действия; функции клиента и `validationRegexp` отключены.

## Проверки

Из корня репозитория:

```sh
pnpm test:components
# или
make test-components
```

PostgreSQL и доступ к модели не нужны. В VS Code тесты находятся в `tests/components.test.ts` и сгруппированы по именам компонентов.

Проверяется следующее:

- JSON Schema компилируется; опечатки в ключевых словах и неразрешимые `$ref` приводят к ошибке;
- файлы схем, примеров и список компонентов совпадают;
- у компонента существуют модель SDK и реализация Lit;
- каждый положительный пример проходит локальную схему, модель SDK и сборку A2UI с проверкой ссылок;
- отрицательные примеры, пропущенные ID, неправильные имена и неизвестные свойства отклоняются;
- агент получает эти же схемы, а сервер применяет изменённые ограничения.

Полный прогон с PostgreSQL дополнительно проверяет, что сервер использует каталог, закреплённый за диалогом. Изменение файлов применяется к новым диалогам после перезапуска; старые продолжают использовать сохранённый документ. Кэш валидаторов учитывает содержимое схем, поэтому разные версии не подменяют друг друга.

Сохранённый документ не устанавливает прежнюю версию renderer в браузер. После изменения клиента проверьте старые диалоги отдельно: поддержка их компонентов и значений должна сохраняться в новой сборке.

Совместимость с renderer проверяется на примерах и затем официальным валидатором каждого ответа. Успешный прогон не доказывает корректность всех возможных комбинаций произвольно изменённой схемы.

## Экспорт

```sh
node scripts/export-catalog.ts > /tmp/a2ui-catalog.json
```

Получится единый документ, собранный из этих файлов. Его можно использовать через существующие источники local, HTTPS или MCP. Внешний источник пока должен совпадать с собранным локальным профилем. Постоянные ограничения действий, ссылок и глубины UI дополнительно проверяются в `packages/core/src/ui.ts`.
